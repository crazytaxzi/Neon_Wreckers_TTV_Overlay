## Pre-Change Commands Contract Summary

- `AdminApp` owns `commands`, `setCommands`, authentication, navigation, page composition, command loading, and the exact ten-resource refresh.
- `/api/v1/admin/chat-commands` remains request three in the shared `Promise.all`.
- Commands receives the shell-owned records, full-refresh callback, and toast function through props.
- The page owns only `selectedId` and `draft` local state.
- Incoming commands render in response order without client filtering, sorting, grouping, search, or pagination.
- Empty data renders an empty existing list container with no empty-state copy.
- New-command defaults, action-value mapping, labels, copy, classes, icons, tones, variants, and accessibility behavior are recorded in `docs/CURRENT_TASK.md`.
- Create uses body-preserving `POST /api/v1/admin/chat-commands`.
- Update uses body-preserving `PUT /api/v1/admin/chat-commands/:encoded-id`.
- Retirement uses bodyless `DELETE /api/v1/admin/chat-commands/:encoded-id` after exact browser confirmation `Retire <trigger>?`.
- Successful save and retirement each invoke the complete refresh exactly once.
- Failed and cancelled commands perform no refresh.
- Existing update refresh replaces an existing selected draft.
- Existing create refresh leaves the unselected local draft open and stale.
- Existing retirement clears only the selected identifier, leaving the stale draft open in create mode after refresh.
- No loading flag, optimistic update, duplicate-submit prevention, state reset, editor close, or new disabled state exists.
- The server is authoritative for authorization, validation, trigger normalization, duplicate detection, availability, ordering, persistence, audit, Twitch execution, StreamElements gates, point costs, and failures.
