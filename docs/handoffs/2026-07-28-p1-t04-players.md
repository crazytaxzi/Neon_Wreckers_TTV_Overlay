### Local state and search

- Search query default remains `""`.
- Selected player default remains `null`.
- Credits, XP, and reputation adjustment defaults remain numeric `0`.
- Audit reason default remains `Operator correction`.
- Search remains client-side and case-insensitive over the combined display name and Twitch login.
- Search remains untrimmed and unnormalized, without fuzzy matching or tokenization.
- Empty loaded or filtered lists remain the existing empty list container without new copy.

### Selection and refresh behavior

- Selecting a player stores the current complete object and opens the modal.
- The existing modal close callback sets selection to `null`.
- Selection clears only when the selected identifier disappears from refreshed props.
- Selection is not replaced merely because a refreshed object has the same identifier.
- After a successful command, the modal remains open when the identifier still exists.
- Adjustment values, reason, selected object, and modal state remain unchanged.
- No optimistic update, loading flag, duplicate-submit prevention, form reset, selected-object reconciliation, or new disabled state was added.

### Browser input conversion

All three adjustment inputs continue using `Number(event.target.value)`.

Preserved consequences include blank-to-zero, negative values, decimal values, browser-rejected nonnumeric input normally becoming an empty value and then zero, and programmatic `NaN` serializing as `null` in an object property. The browser still does not clamp, round, or validate server integer ranges before sending.

### Exact player commands

Adjustment remains:

```text
POST /api/v1/admin/players/:id/adjust
JSON.stringify({ credits, xp, reputation, reason })
```

Individual cooldown reset remains:

```text
POST /api/v1/admin/players/:id/cooldowns/reset
JSON.stringify({ actionKey: cooldown.actionKey, reason })
```

All-cooldowns reset remains:

```text
POST /api/v1/admin/players/:id/cooldowns/reset
JSON.stringify({ reason })
```

Every command retains:

- Method `POST`.
- No browser confirmation.
- Success title only with tone `success`.
- Adjustment title `Player balances updated`.
- Individual cooldown title `Cooldown reset`.
- All-cooldowns title `All cooldowns reset`.
- Exactly one awaited full refresh after success.
- Failure title `Admin command failed`, message `errorMessage(error)`, and tone `danger`.
- No false success and no refresh after failure.
