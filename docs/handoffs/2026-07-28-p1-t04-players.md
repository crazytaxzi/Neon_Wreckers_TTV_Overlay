All three adjustment inputs continue using `Number(event.target.value)`.

The preserved behavior includes blank-to-zero conversion, negative values, decimal values, browser-rejected nonnumeric input normally becoming an empty value and therefore zero, and programmatic `NaN` serializing as `null` in an object property. The browser still does not clamp, round, or enforce server integer ranges before sending.

### Exact player commands

Adjustment remains:

```text
POST /api/v1/admin/players/:id/adjust
JSON.stringify({ credits, xp, reputation, reason })
```

Individual cooldown reset remains:

```text
POST /api/v1/admin/players/:id/cooldowns/reset
JSON.stringify({ actionKey: cooldown.actionKey, reason })
```

All-cooldowns reset remains:

```text
POST /api/v1/admin/players/:id/cooldowns/reset
JSON.stringify({ reason })
```

Every command retains:

- Method `POST`.
- No browser confirmation.
- Success title only with tone `success`.
- Adjustment title `Player balances updated`.
- Individual cooldown title `Cooldown reset`.
- All-cooldowns title `All cooldowns reset`.
- Exactly one awaited full refresh after success.
- Failure title `Admin command failed`, message `errorMessage(error)`, and tone `danger`.
- No false success and no refresh after failure.
